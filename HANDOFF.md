This repository holds every landing-site design made for **NetRate** («نت‌ریت»), a mobile app that shows, side by side,
the pound → toman rates that UK exchange offices post themselves. The owner is **Mohammad** (writes Persian; answer him
in Persian; code, comments and file names in English). He views everything as claude.ai artifacts and does not run
things locally, so every finished piece is also published or exported as a file he can open.

Read these, in this order:

1. **This file** — where things stand and how to continue.
2. **`CLAUDE.md`** — the project's memory: the NetRate brief (hard rules), every round of the owner's feedback, the
   build commands, and the pitfalls already hit. It is long because every line was paid for; follow it.
3. `site/studies/README.md` — the NetRate × studies track (the current work) in detail.
4. `studies/README.md` — the six reference rebuilds (the structures the NetRate pages are built on).

## The rules that never bend (the NetRate brief — full list in `CLAUDE.md`)
- NetRate **is not an exchange office and never moves money**: no “send money”, “convert”, money/flag/arrow-circle icons.
- Before release: “Coming soon”, never a download promise. No competitor names, rate predictions, store/ranking
  promises, fake users / stats / ratings / testimonials, regulator logos, or the client's name.
- Every number shows its age and is labelled demo data. Colour only for direction (up blue, down coral, never green);
  gold only for the paid Featured spot; nothing marks “best”.
- Verbatim: “NetRate is not an exchange office and never moves money.” and “The offices post the rates themselves, for
  information only; for a firm rate, contact the office before you deal.”
- Text ≥ 14 px (`max(14px, …)` on scaled text), touch targets ≥ 44 px, AA contrast, `prefers-reduced-motion` respected,
  no cookies or trackers, footer signature `DESIGNED & DEVELOPED BY — M.S` + Telegram https://t.me/Mohammad_s203.
- The app (`site/app/netrate-demo.html`) is a black box: only its public hooks; app screens are rendered from it.
- Owner's design decisions for the studies track: keep the study's structure; the app's English version; show the
  phone/app in two places at most (hero + App Store page) plus one showcase; Inter Tight (headings, numbers) + Inter
  (text); no outlined letters; a cool off-white ground with white boxes, dot patches and dot floors; smooth scrolling.

## How to build (from the repo root; Python 3, Node with Playwright, Chromium)
```bash
node site/studies/01-fintech/tools/shots.js          # app screens from the app itself (3x) → img/raw (gitignored)
python3 -I site/studies/01-fintech/tools/convert.py  # → img/app/*.webp (600 / 1170 px) + tops.json
python3 -I site/studies/01-fintech/tools/build.py    # page.html → index.html + live.html, then tools/pages.py for both
python3 -I site/studies/tools/build_artifact.py 01-fintech   # → dist/netrate-01-fintech/ (artifact fragment)
python3 -I studies/tools/build_gallery.py            # → dist/studies/ (the gallery artifact)
python3 -I tools/export.py                           # → exports/ (zips + single HTML files)
python3 -m http.server 8099                          # then open http://127.0.0.1:8099/site/studies/01-fintech/
```
Edit **`page.html`** (never the generated `index.html` / `live.html`): `<!--pre-->…<!--/pre-->` and
`<!--post-->…<!--/post-->` blocks keep text in one version only; `{{shot:scene:kind}}`, `{{stores}}`, `{{body}}` … are
listed at the top of `tools/build.py`. The other pages' copy is in `tools/pages.py`. Styles: `style.css` (one file for
every page; sizes scale with `--u` = page width / 1440, capped at 2200 px). Motion: `main.js` (GSAP + ScrollTrigger +
Lenis; complete at rest without it).

## How to start the next design (6, then 2) — when Mohammad says so
1. Study the reference rebuild: `studies/06-invest/` (its sections, grid, sizes, motion) and its sheet
   `studies/refs/sheets/06.jpg`. Keep that structure; change the content to NetRate's.
2. Create `site/studies/06-invest/` the way design 1 is made: `page.html` with pre/post blocks, `style.css`, `main.js`,
   `tools/build.py` (copy and adapt design 1's), app screens via a `shots.js` (copy design 1's JOBS list and pick the
   scenes), the other pages via a `pages.py` (design 1's works with any header/footer that follow its markup).
3. Copy and facts: reuse design 1's vetted English and Aurora's `site/variants/aurora/src/i18n/en.json`; every claim must
   pass the brief.
4. Gallery: add `6a` / `6b` entries to `NETRATE` in `studies/index.html` (status built, src `netrate/06-invest/…`), add
   `'06-invest'` to `NETRATE` in `studies/tools/build_gallery.py`, thumbnails `studies/thumbs/nr-6a.jpg`, `nr-6b.jpg`.
5. QA (see `CLAUDE.md` → QA): 1440 / 1920 / 1024 / 390, no horizontal scroll, console clean, text ≥ 14 px, targets
   ≥ 44 px, contrast, reduced motion shows the finished layout.
6. Rebuild the gallery and the standalone artifact, run `tools/export.py`, update `CLAUDE.md` + READMEs, commit, push,
   and tell Mohammad in Persian with the links. Then wait for his word before design 2.

## Release checklist (when the app ships)
- Real store links in place of the `data-store` notes; switch the published site to the after-release version
  (`live.html` → the site's `index.html`, `live-*.html` → plain names; `tools/export.py` already does this).
- Fill every `[placeholder]` in the legal pages and get them reviewed; remove the “Draft for review” notes
  (`DRAFT` in `tools/pages.py`).
- Domain: canonical URLs, `sitemap.xml`, `robots.txt`, Open Graph images for link previews.
- Consider self-hosting the fonts and GSAP/Lenis (the Cookies page mentions these outside requests).
